# Contribution Guidelines

## Inclusion Criteria

This list gets a lot of low-effort and auto-generated pull requests.
To keep it useful, a project is only added if it meets all of the following:

1. **Age:** The project has existed for at least 4 months
    (based on its first release, repository creation, or domain registration).
2. **Adoption:** The project has at least 100 GitHub stars
    or independent third-party coverage
    (e.g. a Wikipedia article, reviews, articles,
    or forum discussions not written by its authors).
    Link this evidence in the pull request.
3. **Disclosure:** If you are an author of the project or affiliated with it,
    say so in the pull request.
    Your own projects are welcome if they meet the criteria above.
4. **Your own words:** Write the pull request description yourself
    and explain how you have used the project.

Pull requests that don't meet these criteria will be closed.

Corrections (broken links, moved or renamed projects, typos,
outdated descriptions) are exempt and always welcome.

## Format

Please ensure your pull request adheres to the following guidelines:

- Make an individual pull request for each suggestion.
- Chose corresponding section for your suggestion.
- Use the following format:
    `[resource-name](link) (commercial) - description plus dot. `
- Label commercial products accordingly,
    but don't add `(open-source)` or similar as list is per default open source.
- List should be alphabetically after your addition.
- New categories and improvements to the existing categorisation are welcome.
- Each line must be a maximum of 80 characters wide.
- No opinion-laden words like "easy", "beautiful", "simple", or similar.
